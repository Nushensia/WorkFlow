# Цепочка документов: Протокол → Паспорт → Отчёт

## Схема

```
Входящие документы (заказчик)
       ↓
  Ввод заказа (input_order.py / вручную)
  → Заказы/П-XXX_Заказчик/ + JSON-карточка
       ↓
┌──────────────────────┐
│   ПРОТОКОЛЫ           │  — результаты каждого вида испытаний
│   испытаний           │    (свои: ВИК, УЗТ, хим. и др.;
└──────────────────────┘     сторонние: ФА, мех., SEM, спец.)
       ↓
┌──────────────────────┐
│   ПАСПОРТ             │  — сводный документ, объединяющий
│   (на объект)         │    все протоколы. Только факты.
│   промт ↓             │    Промт: Промт/prompt_passport_template.md
└──────────────────────┘
       ↓
┌──────────────────────┐
│   ОТЧЁТ               │  — паспорт + обсуждение + выводы
│                       │    + заключение + рекомендации
└──────────────────────┘
```

## Виды документов

### 1. Протоколы испытаний
Документ на каждый вид испытания. Оформляется лабораторией (своей или сторонней).
- **ВИК** — визуальный и измерительный контроль
- **УЗТ** — ультразвуковая толщинометрия
- **Химический анализ**
- **Анализ технологического осадка**
- **Металлография**: оптическая микроскопия, SEM/EDS, микротвёрдость
- **Измерение твёрдости** (макро)
- **Механические испытания**
- **Специальные**: SSC, HIC, длительная прочность, **ФА** (физ.-хим. фазовый анализ) — по необходимости

### 2. Паспорт
Сводный документ, объединяющий все протоколы по одному объекту.  
Структура: введение → программа → результаты по видам испытаний.  
Без выводов/заключения — только факты.

### 3. Отчёт
Паспорт + аналитическая часть:
- **4. Обсуждение результатов** — анализ механизма разрушения/деградации (опционально)
- **5. Выводы** — детальные пункты по каждому виду испытаний
- **6. Заключение** — итоговый вердикт (годен/не годен, причина дефектов)
- **7. Рекомендации** — конкретные действия (замена/ремонт/мониторинг)

## Схема приёмки заказа
Два варианта работы с новыми данными:

### А — папка `Входящие/`
Заказчик/завод кладёт документы в `Входящие/`. Я просматриваю, разбираю структуру, запускаю `input_order.py`, который копирует файлы в `Заказы/П-XXX_Заказчик/`.

### В — диалог (`input_order.py`)
Скрипт спрашивает номер заказа, заказчика, объект, материал, выбирает виды испытаний, запрашивает файлы протоколов. Создаёт:
```
Заказы/П-XXX_Заказчик/
├── П-XXX_данные.json
├── Протоколы/
├── Паспорт/
└── Отчёт/
```

## Правила совместной работы OpenCode + Hermes

Агенты работают **асинхронно** — не обязательно одновременно.

### Принципы
1. **Один агент = одна сессия.** Открыли, поработали, закрыли.
2. **Файлы — единственный канал связи.** plan.md = что делать, log.md = что сделано.
3. **Читай перед тем как писать.** Перед работой — прочитать plan.md и log.md.

### Соглашения
- `plan.md` — список задач. Кто увидел незакрытый пункт — может взять.
- `log.md` — лог действий. Каждая запись с подписью: `(OpenCode)` или `(Hermes)`.
- **Не удалять чужие файлы.** Если нужно переименовать/перенести — спросить в log.md.
- **Не переписывать то, что уже сделано.** Проверить log.md прежде чем начинать.
- Если задача требует двух агентов — первый пишет в log.md «требуется помощь по ...» и закрывается. Второй читает и подхватывает.

### Пример цикла
```
1. [OpenCode] Заполнил JSON, написал в log.md "JSON готов, жду шаблон" → закрыл
2. [Hermes]   Прочитал log.md, создал шаблон, обновил log.md → закрыл
3. [OpenCode] Прочитал log.md, увидел шаблон, продолжил
```
