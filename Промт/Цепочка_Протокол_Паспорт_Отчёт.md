# Промт: Оптимизация цепочки «Протокол → Паспорт → Отчёт»

## Контекст
Заказчик присылает образцы металла и сопроводительные документы. Лаборатория проводит испытания (часть — своими силами, часть — через сторонние организации). Результаты оформляются в виде цепочки документов:

1. **Протоколы испытаний** — на каждый вид испытания
2. **Паспорт** — сводный документ, объединяющий все протоколы по одному объекту (только факты)
3. **Отчёт** — паспорт + аналитика: обсуждение, выводы, заключение, рекомендации

## Проблемы
- Протоколы приходят из разных источников в разном формате
- Нет единого генератора паспортов
- Много ручной работы по компоновке, форматированию, сверке

## Цель
Автоматизировать конвейер: **входные данные → протоколы → паспорт → отчёт**

## Схема работы

```
Входящие документы (заказчик)
       ↓
  input_order.py — сканирует Входящие/, спрашивает данные
  → создаёт папку Заказы/П-XXX_Заказчик/
  → копирует файлы
  → генерирует JSON-карточку с перечнем и статусом испытаний
       ↓
  Протоколы испытаний (по видам)
  — свои (ВИК, УЗТ, хим., осадок, оптика, твёрдость)
  — сторонние (ФА, мех., SEM, SSC, HIC, длит. прочность)
       ↓
  Паспорт (сводка фактов, без выводов)
       ↓
  Отчёт (паспорт + обсуждение + выводы + заключение + рекомендации)
```

## Структура паспорта
1. **Титульный лист**
2. **Введение** (1.1–1.6)
3. **Программа исследования** (2.1 Образцы, 2.2 Методы)
4. **Результаты исследования** (3.1–3.9 по видам испытаний)
5. **Заключение** (констатация фактов, без вердикта)
6. **Приложения** (П-1…П-N)

## Структура отчёта
1. **Введение** (1.1–1.6)
2. **Программа исследования** (2.1 Образцы, 2.2 Методы)
3. **Результаты исследования** (по видам испытаний)
4. **Обсуждение результатов** (опционально)
5. **Выводы**
6. **Заключение** (вердикт, 1 абзац)
7. **Рекомендации** (опционально)
8. **Приложения** (П-1…П-N)
