# Промт: Генерация отчёта из паспорта

## Назначение
На основе готового паспорта объекта исследования создать **Отчёт** — документ, содержащий паспортные данные + выводы + заключение + рекомендации.

## Принцип энергоэффективности
**НЕ перегенерировать то, что уже есть.**
- Паспорт уже содержит все факты — не пересоздавать их
- Протоколы испытаний — не перегенерировать, подтянуть как приложения
- AI-генерация только для: выводов, заключения, рекомендаций
- Hermes подключается для поиска литературы (arxiv, sci-search, ГОСТы)

## Источники

### 1. Паспорт (обязательно)
`Заказы/{номер}_{заказчик}/Паспорт/Паспорт_{номер}_{заказчик}.docx`
Содержит: титул, введение, программу, результаты, заключение-констатацию.

### 2. Протоколы испытаний (подтягиваются, не создаются)
`Заказы/{номер}_{заказчик}/Протоколы/`. Каждый протокол — отдельный DOCX.
Используются как приложения к отчёту (Приложение № П-1…П-N).

### 3. JSON-карточка заказа
`Заказы/{номер}_{заказчик}/{номер}_данные.json`

## Структура отчёта (по исходнику П-674)

### Титульный лист
- «**УТВЕРЖДАЮ**» — по левому краю, 12 pt
- «Генеральный директор АО «НПО «Ленкор»» — 12 pt
- Линия подписи + дата: «______________ Андржеевский В.Э. / «___» _____________ 20__ г.»
- Пустая строка
- «**ОТЧЁТ**» — крупно, **по центру**, 16-18 pt, полужирный
- «по результатам комплексного исследования металла» (или полное название объекта) — по центру, 14 pt
- Архивный номер: «арх. № ДЭЗ – XXX – XXXXX – 20XX» — по правому краю, 12 pt
- Несколько пустых строк для вертикального центрирования
- «г. Санкт-Петербург» / «20__ г.» — внизу по центру

## Варианты отчёта

Отчёт может быть двух видов в зависимости от сложности:

### Базовый (один объект, простой случай)
Структура без «Обсуждения»:
1. Введение → 2. Программа → 3. Результаты → 4. Выводы → 5. Заключение → 6. Рекомендации → Приложения

### Расширенный (много объектов / анализ разрушения)
Структура с «Обсуждением» и группировкой по объектам:
1. Введение → 2. Программа → 3. Результаты (по объектам) → 4. Обсуждение → 5. Выводы → 6. Заключение → 7. Рекомендации → Список литературы → Приложения

Раздел «Обсуждение» — **только для сложных случаев**: разбор механизма разрушения/деградации со ссылками на литературу. В простых отчётах исключается.

### Содержание (Table of Contents)
Нумерованные разделы с номерами страниц:
1. Введение
   - 1.1 Основание для проведения исследования
   - 1.2 Сведения об экспертной организации
   - 1.3 Сведения об экспертах
   - 1.4 Цель исследования
   - 1.5 Перечень рассмотренной документации
   - 1.6 Характеристика объекта исследования
2. Программа исследования
   - 2.1 Образцы
   - 2.2 Методы исследования
3. Результаты исследования
   - 3.1 Анализ документации
   - 3.2 Визуальный и измерительный контроль (ВИК)
   - 3.3 Химический анализ
   - 3.4 Анализ технологического осадка
   - 3.5 Металлографическое исследование
     - 3.5.1 Оптическая микроскопия
     - 3.5.2 Сканирующая электронная микроскопия (SEM/EDS)
     - 3.5.3 Микротвердость
   - 3.6 Результаты измерения твердости
   - 3.7 Механические испытания
   - 3.8 Специальные испытания
     - 3.8.1 Физико-химический фазовый анализ
4. **Выводы** — генерируется AI
5. **Заключение** — генерируется AI
6. **Рекомендации** — генерируется AI
Приложение № П-1…П-N

### Формат оформления

#### Титульный лист
- «ОТЧЕТ» — 16-18 pt, полужирный, по центру
- Полное название — 14 pt, по центру
- Архивный номер — 12 pt, по правому краю
- Блок утверждения: «Генеральный директор ... линия ... дата»
- Внизу: «г. Санкт-Петербург / 2026 г.» — по центру, 12 pt

#### Содержание
- Заголовок «Содержание» — полужирный, 14 pt
- Строки: номер раздела + название + табуляция + номер страницы
- Формат: «1.\tВведение\t3», «1.1\tОснование...\t3»

#### Разделы
- Заголовки разделов (1., 2., 3., 4., 5., 6.) — полужирный, 14-16 pt
- Подразделы (1.1, 1.2, …) — полужирный или обычный, 12-14 pt
- Основной текст — Times New Roman, 12 pt, межстрочный 1.5, выравнивание по ширине
- Абзацный отступ — 1.25 см

#### Таблицы
Два типа оформления:

**Тип 1 — Word-таблица** (программа, механика, твёрдость, металлография):
- Подпись сверху: «Таблица X – Название» — по центру или левому краю, 10-11 pt, не жирный
- Шапка — полужирный, 10 pt, заливка #D9E2F3
- Данные — 9-10 pt, обычный, по центру
- Границы — Table Grid

**Тип 2 — табулированные параграфы** (химический состав):
- Элементы через табуляцию, каждый параграф по центру
- Заголовки: «Образец | Массовая доля % | Fe | C | Si | Mn | Cr | Mo | S | P | Ni | Cu» — 10 pt, полужирные
- Строки данных — 10 pt, обычный
- Разделители между группами строк — пустые параграфы

#### Рисунки
- Изображения вставляются в документ
- Подпись: «Рисунок X – Название» — по центру, не жирный, 11-12 pt
- Подписи к подрисункам: а), б), в) — внутри области рисунка или отдельными строками
- Нумерация рисунков сквозная по всему отчёту

#### Ссылки на литературу
- В тексте: в квадратных скобках [1], [2, 3], [4-6]
- Список литературы — в конце отчёта (или в приложении)
- Формат: автор, название, источник, год, страницы

#### Ссылки на приложения
- В тексте каждого раздела: «Результаты ... представлены в Приложении № П-N.»
- Каждый вид испытаний ссылается на своё приложение

#### Подписи
Блок подписей в конце отчёта:
- Технический директор + ФИО
- Заведующая лабораторией + ФИО
- Зам. технического директора + ФИО
- Специалисты + ФИО
- Каждая подпись: должность (слева), линия, ФИО (справа)

#### Приложения
«Приложение № П-N. Название» — заголовок, 14 pt, полужирный
Далее — вложенные протоколы, таблицы, рисунки
**Последнее приложение** — всегда «Приложение № П-N. Список нормативной документации и использованной литературы» (НТД).
Если приложение не применяется в данном отчёте — не включается, номера сдвигаются.

## Что НЕ нужно делать
- ❌ Не пересоздавать протоколы — они уже есть
- ❌ Не переписывать факты из паспорта — они уже изложены
- ❌ Не генерировать титул, содержание, введение, программу — взять из паспорта
- ❌ Не добавлять пустые разделы — только то, что применимо
- ❌ Не добавлять «Обсуждение результатов» — в реальных отчётах его нет (раздел 4 сразу Выводы)

## Что нужно сделать AI
- ✏️ Раздел 4. Выводы (по пунктам, на основе фактов из паспорта)
- ✏️ Раздел 5. Заключение (итоговый вердикт, 1-2 абзаца)
- ✏️ Раздел 6. Рекомендации (конкретные действия)
- 🔗 Подтянуть протоколы как приложения (ссылки, не перегенерация)
- 🔗 [Hermes] Поиск литературы: статьи, ГОСТы, справочные данные

## Процесс сборки
```
Паспорт (DOCX)                 Протоколы (DOCX)
      |                              |
      ↓                              ↓
  Взять всё содержимое     Подтянуть как приложения
  (разделы 1–3 +           (П-1 ВИК, П-2 Химия, ...)
   заключение)
      |                              |
      └──────────────┬───────────────┘
                     ↓
          ОТЧЁТ (черновик)
                     ↓
  ┌────────────────────────────────────────┐
  │ [Hermes] Поиск литературы:            │
  │ — статьи (arxiv, sci-search)          │
  │ — ГОСТы, НТД                          │
  │ — аналоги, справочные данные          │
  └────────────────────────────────────────┘
                     ↓
  [OpenCode] пишет разделы 4–6
  (Выводы, Заключение, Рекомендации)
  + оформляет список литературы
                     ↓
  [Hermes] проверяет форматирование,
  подтягивает приложения-протоколы
                     ↓
  Сохранить как Отчёт_{номер}_{заказчик}.docx
```

## Роли в процессе
| Кто | Роль | Что делает |
|-----|------|-----------|
| **OpenCode** | Документовед | Разбирает входящие, заполняет JSON, пишет выводы/заключение/рекомендации, финальная вычитка |
| **Hermes** | Инженер автоматизации | Ищет литературу (arxiv, sci-search, ГОСТы), создаёт генераторы/шаблоны, проверяет форматирование, подтягивает протоколы, чинит DOCX |
